# 设计原则 / Design Principles

> 官方指南：https://m3.material.io/ ｜ https://developer.android.com/design
> 核验日期：2026-11-14
> 状态：原则层是定性结论，不涉及版本号；官方站点正文为动态渲染，本条基于官方站点结构与公开材料整理，交付前建议人工复核。

## M3 的三条核心原则

| 原则 | 含义 | 落地表现 |
|---|---|---|
| Personal / 个性化 | 界面属于「这个用户」 | Dynamic color、深浅主题、可配置密度 |
| Adaptive / 自适应 | 一套界面适配不同窗口与设备 | 由窗口尺寸类驱动布局，而非设备型号 |
| Expressive / 表现力 | 用动效、形状、字阶表达层级与情绪 | 有目的的运动、形状 morph、强调字阶 |

优先级：**Adaptive > Personal > Expressive**。
一个屏幕如果在小屏上信息挤成一团，再漂亮的 expressive 动效也不成立。

## 从任务到组件的推导顺序

固定按这个顺序走，不要从「我想用个 FAB」开始：

1. 用户此刻要完成的一件事（primary action）
2. 这件事在界面上的层级（主 / 次 / 三）
3. 承载它的容器与导航结构
4. 用哪个官方组件
5. 颜色 / 字体 / 形状 / 动效的语义角色
6. 窗口变化时如何重排
7. 无障碍与文本缩放下是否仍成立

跳过 1-3 直接选组件，是绝大多数「做得挺好看但用起来别扭」的界面成因。

## 一致性边界

- **必须一致**：语义色角色、字阶、形状层级、间距节奏、导航模式、返回行为。
- **可以变化**：品牌色相、具体 radius 数值、字体族、动效风格。
- **禁止**：同一含义在不同屏幕用不同角色。例如「危险」在一个页面用 `error`，在另一个页面用红字配 `surface`。

## Expressive 的适用判断

用 M3 Expressive 前回答三个问题，任一为「否」就别用：

1. 当前 material3 版本是否已把该 API 从 `@ExperimentalMaterial3ExpressiveApi` 转正？
2. 这个动效是否帮助用户理解「状态从哪来、到哪去」？
3. 关掉动效后信息是否仍然完整？

Expressive 不是默认值。**任务清晰度永远优先于表现力。**

## 反模式

- 把「好看」当需求，先定视觉再补功能。
- 用单张设计稿交付，不写交互状态、空态、错误态。
- 用自定义组件替代官方组件，却说不出官方组件哪里不适用。
- 用设备型号（手机 / 平板）判断布局，而不是窗口宽度。
- 只在浅色主题下验证。

- [ ] 语义色、字阶、形状、间距四套系统没有互相打架

- [ ] 浅色 / 深色 / 200% 字体缩放三种状态都看过
