# Android UI Rules

> 定位：写界面时的**决策规则**，不是组件目录。每条都能被判定「做了 / 没做」。
> 核验日期：2026-11-14 ｜ 配套：`compose-coding-rules.md`（代码层）、`ui-review-checklist.md`（验收层）

## A. 顺序

**A1. 先定任务，再定组件。**
写第一行代码前，先写出一句话：「这个屏幕让用户完成 ___」。写不出来的屏幕，先别做。

**A2. 先定信息层级，再定视觉。**
主操作、次要信息、辅助信息三层必须能标出来。一个屏幕只允许一个视觉最强点。

**A3. 导航结构先于页面内容。**
先确定 App 级导航模式（NavigationBar / Rail / Drawer），再往里填页面。反过来做，后期必然重构。

## B. 组件选择

**B1. 官方组件优先。**
`androidx.compose.material3` 里有能用的，就不要自己拼。自定义前必须能回答：「官方组件的哪个具体限制无法满足？」答不出就用官方的。

**B2. 一个屏幕的主操作只能有一个 Filled 样式的强调按钮。**
多个同级强调 = 没有强调。

**B3. 列表用 `LazyColumn` / `LazyRow`，不用 `Column` + `forEach`。**
超过一屏的内容必须虚拟化。

**B4. 输入类交互优先用现成组件，不自造。**
日期 → `DatePicker`，时间 → `TimePicker`，下拉选择 → `ExposedDropdownMenuBox`。自造这些控件的无障碍成本远高于预期。

## C. 视觉系统

**C1. 颜色只通过语义角色使用。**
组件内不出现裸 `Color(0x...)`；也不出现 `Color.White` / `Color.Black` 做文字色。

**C2. 字号只从字阶取。**
不写「16sp 标题」，写「Title Medium」。见 `01-Foundations/typography.md`。

**C3. 圆角只从形状档位取。**
4 / 8 / 12 / 16 / 28 或胶囊。不出现 10dp、11dp 这类中间值。

**C4. 间距成体系。**
基准 4dp，常用 4 / 8 / 12 / 16 / 24 / 32。任意数值的间距会让界面「说不上哪里怪」。

**C5. 浮层用表面色阶表达层级，不用大阴影。**
见 `01-Foundations/elevation.md`。

## D. 主题与适配

**D1. 浅色 / 深色主题都必须定义。**
只做浅色不是「先做一半」，是交付不完整。

**D2. Dynamic color 必须有 fallback。**
关掉主题色、API 31 以下设备，界面仍要完整可用。

**D3. 布局跟着窗口宽度走，不跟着设备型号走。**
用 `WindowSizeClass` 判断，不写 `if (isTablet)`。

**D4. edge-to-edge 是默认，不是可选项。**
必须处理状态栏 / 导航栏 / IME inset。不能让内容被系统栏压住。

**D5. 横屏和大屏要单独看一眼。**
至少验证：内容不被拉伸成全宽长行、抽屉 / Rail 切换正常、弹出层不超出边界。

## E. 状态

**E1. 四个状态齐全：加载 / 空 / 错误 / 有内容。**
只做「有内容」是 demo，不是产品。

**E2. 空态要给出下一步动作。**
「暂无数据」后面必须跟一个能点的按钮或说明。

**E3. 错误要可恢复。**
给出重试入口，并说明失败原因（用户能看懂的话，不是堆栈）。

**E4. 破坏性操作必须可撤销或二次确认。**
删除优先用 Snackbar + 撤销，而不是弹窗。真正的不可逆操作（清空账号）才用确认对话框。

## F. 无障碍

**F1. 触控目标 ≥ 48dp。**
图标按钮尤其容易漏。

**F2. 不靠颜色单独传达状态。**
错误、选中、必填都要有非颜色的第二信号。

**F3. 200% 字体缩放下不能崩。**
固定高度容器是最常见的原因。

**F4. 每个可交互元素都能被 TalkBack 正确朗读。**
自定义 `clickable` 的容器要补 `role` 和语义。

## G. 边界

**G1. 不用单张设计稿替代交互说明。**
交付必须包含：交互状态、过渡、空 / 错 / 载三态、边界情况。

**G2. 不把个人审美写成规则。**
「我觉得这样好看」不是理由。要么引官方指南，要么承认这是产品决策。

**G3. 不确定的规范必须标注。**
写「据官方指南 xxx（核验日期：YYYY-MM-DD）」，而不是「Material 规定」。

## 判定优先级

冲突时按此顺序取舍：

**可用性 > 无障碍 > 一致性 > 表现力 > 个人偏好**

例如：一个 expressive 动效让 TalkBack 焦点跳错，删动效，不改无障碍。
